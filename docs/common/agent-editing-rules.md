# Правила внесения изменений в код

Правки `.md`: те же требования к плану и подтверждению, что для кода; разметка — по [markdown-conventions.md](markdown-conventions.md).

## Перед применением

- Показывать план изменений
- Получать подтверждение пользователя
- Показывать diff перед применением
- Не применять изменения автоматически без явного согласия

## Во время правок

- Добавлять русские комментарии для сложной логики
- Объяснять внесённые изменения на русском языке
- Сохранять английские названия переменных и функций
- Следовать принципам чистого кода

## 🚨 Сохранение комментариев

**КРИТИЧНО:** Всегда сохранять существующие комментарии при редактировании кода.

- Не удалять существующие комментарии, если код остаётся
- Добавлять новые комментарии для нового кода
- Обновлять комментарии только если они относятся к изменяемому коду

### Пример корректного поведения

```typescript
// Существующий комментарий - СОХРАНИТЬ!
function oldFunction() {
	// Важная логика - СОХРАНИТЬ!
	return data;
}

// Новый комментарий для новой функции
function newFunction() {
	// Объяснение новой логики
	return newData;
}
```

**Исключения** (когда можно удалить комментарий):

- Комментарий относится к удаляемому коду
- Пользователь явно попросил удалить конкретный комментарий
- Комментарий содержит устаревшую информацию об изменяемом коде

## Чеклист редактирования

- [ ] План изменений показан пользователю
- [ ] Получено подтверждение пользователя
- [ ] Все существующие комментарии сохранены
- [ ] Добавлены русские комментарии для сложной логики
- [ ] Названия переменных/функций на английском
- [ ] После внесения изменений проверены сообщения линтера (ReadLints) и исправлены найденные ошибки
