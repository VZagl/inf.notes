# git-commit — Генерация сообщения коммита

**Назначение:** При вызове `/git-commit` сгенерируй сообщение коммита на основе staged-файлов по правилам Conventional Commits. Покажи сообщение пользователю, дождись подтверждения и выполни коммит только после явного согласия.

**Источники правил:** `docs/common/git-commit-description.md`, `.cursor/rules/git.mdc`

---

## Алгоритм

### Шаг 1. Проверить наличие staged-файлов

1. Выполни `git status`.
2. Если нет staged файлов — сообщи об этом и заверши. Не добавляй файлы сам — пользователь добавит через `git add` при необходимости.
3. Выполни `git diff --staged`.
4. Если diff пуст — выведи «Нет файлов, добавленных для коммита.» и заверши.
5. **Принцип:** один коммит — одна логическая задача. Если staged-изменения нарушают это (несколько несвязанных задач, слишком крупный объём) — выведи предупреждение с кратким описанием, предложи варианты и дождись решения. Пользователь либо выбирает предложенный вариант (тогда выполни его), либо делает сам (тогда заверши):
   - **Дробить:** снять часть файлов из staged (`git reset HEAD <файл>`), сделать коммит оставшихся, затем добавить остальные и повторить `/git-commit`
   - **Продолжить как есть:** сформировать сообщение для всего объёма и выполнить коммит
   - **Отменить:** снять все из staged (`git reset HEAD`) и завершить без коммита

### Шаг 2. Сформировать сообщение коммита

1. Проанализируй изменения: что и зачем изменено.
2. При изменениях в `memory-bank/` примени правило «Приоритет type: memory-bank» из `docs/common/git-commit-description.md`.
3. Сформируй заголовок: `type(scope): описание` (type и scope строчными, описание на русском, повелительное наклонение, до 50 символов).
4. Добавь тело: маркированный список изменений (прошедшее время, безличная форма, до 72 символов на строку).
5. При наличии задачи — футер: `Closes #123` или `Fixes #123`.
6. Полный формат — см. `docs/common/git-commit-description.md`.

### Шаг 3. Показать сообщение и запросить подтверждение

1. Выведи сообщение в кодовом блоке (без обрамляющих ``` в итоговом тексте).
2. Спроси: «Выполнить коммит с этим сообщением? Продолжить?»
3. Дождись явного подтверждения («да», «ок», «выполни», «commit» и т.п.).
4. Если пользователь просит изменить — внеси правки, покажи обновлённое, снова запроси подтверждение.
5. Если пользователь отказывается — заверши без коммита.

### Шаг 4. Выполнить коммит (только после подтверждения)

1. Сохрани сообщение (без обрамляющих ```) в `.git-commit-msg.txt` в корне проекта.
2. **Кодировка:** UTF-8 без BOM. **КРИТИЧНО для Windows:** используй инструмент `Write` — он гарантирует корректную кодировку кириллицы. PowerShell-команды (`Out-File`, `[System.IO.File]::WriteAllText`) могут искажать кириллицу.
3. Выполни `git commit -F .git-commit-msg.txt` (Shell с `required_permissions: ["all"]`).
4. Удали `.git-commit-msg.txt` (Shell с `Remove-Item .git-commit-msg.txt`).

### Шаг 5. Проверить результат

1. Выполни `git log -1 --pretty=format:"%s%n%n%b"` и выведи результат.
2. Если сообщение отображается некорректно (кракозябры вместо кириллицы) — предложи исправить кодировку.
3. При подтверждении исправления:
   - Сохрани сообщение в `.git-commit-msg.txt` через `Write` (UTF-8 без BOM).
   - Выполни `git commit --amend -F .git-commit-msg.txt`.
   - Удали `.git-commit-msg.txt`.
   - Проверь: `git log -1 --format=%B` — кириллица должна отображаться корректно.
   - Выведи подтверждение об успешном исправлении.

---

## Не делать

- **Коммит без подтверждения:** Никогда не выполнять коммит до явного подтверждения пользователя.
- **Кодировка:** Не использовать PowerShell `Out-File` или `[System.IO.File]::WriteAllText` для `.git-commit-msg.txt` — только инструмент `Write`.
- **UTF-8 с BOM:** Файл сообщения — только UTF-8 без BOM.
- **Смешение задач:** Не формировать коммит со смешением задач без предупреждения и явного выбора пользователя «продолжить как есть».

- [ ] При нарушении принципа «один коммит — одна задача»: предупреждение выведено, варианты предложены, решение пользователя получено
- [ ] При изменениях в `memory-bank/` применён «Приоритет type: memory-bank»
- [ ] Сформирован заголовок `type(scope): описание`
- [ ] Добавлено тело с маркированным списком изменений (прошедшее время, безличная форма)
- [ ] Сообщение выведено в кодовом блоке
- [ ] Подтверждение пользователя получено
- [ ] Файл `.git-commit-msg.txt` создан через `Write` (UTF-8 без BOM)
- [ ] Выполнен `git commit -F .git-commit-msg.txt`
- [ ] Файл `.git-commit-msg.txt` удалён
- [ ] Результат проверен (`git log -1`), кодировка корректна
- [ ] Итог выведен пользователю
