# close-task — Финализация задачи

**Назначение:** При вызове `/close-task` выполни следующий алгоритм. Создай completed-запись, удали задачу из backlog (если была), приведи Memory Bank в состояние готовности к следующей задаче.

**Источник task_id:** Секция "Current Task" (приоритет 1) или "Last Completed Task" (приоритет 2, если Current пуст или плейсхолдер).

`{task_id}` — **полный** идентификатор из `tasks.md` (обычно вида `step-…`). Префикс `step-` уже входит в значение; **не** писать `step-{task_id}`.

---

## Алгоритм

### Шаг 1. Определить задачу

1. Прочитай `memory-bank/tasks.md`.
2. Извлеки task_id из "Current Task" или "Last Completed Task".
3. Если task_id не найден — сообщи "Нет активной задачи для финализации" и заверши.
4. Проверь: существует ли `memory-bank/completed-tasks/**/[task_id]*.md`?
   - Если да — сообщи "Задача [task_id] уже финализирована" и заверши.
5. Извлеки: task_id, название, дату создания, дату завершения (текущая дата если нет), уровень сложности, тип.

### Шаг 2. Найти артефакты

- Ищи `memory-bank/archive/archive-[task_id].md` и `memory-bank/archive/*[task_id]*.md`.
- Ищи `memory-bank/reflection/reflection-[task_id].md`.
- Запомни пути (относительно `memory-bank/`).
- **Наличие артефактов** определяет статус в Last Completed Task (см. Шаг 7).

### Шаг 3. Собрать описание для completed-записи

Карточка = копия `memory-bank/completed-tasks/_template.md`: **секции не удалять и не переименовывать**.

- **## Задание:** backlog → tasks/рефлексия/архив. Если не удалось — «Задание не удалось восстановить из доступных источников».
- **## Изменения в задании:** если задание менялось в процессе — описать отличия; если нет — «не было».
- **## Результат:** итоги из tasks.md, рефлексии или архива.
- **## Ссылки:** **Архив:** / **Рефлексия:** / **Ветка:** / **Коммит:**; нет значения — `—`.

### Шаг 4. Определить путь файла

- YYYY/MM — по дате **создания** задачи.
- Имя: `[task_id]_YYYY-MM-DD.md` — дата **завершения**.
- Создай подкаталоги YYYY/MM при необходимости.

### Шаг 5. Показать план и запросить подтверждение

Перед показом: если task_id соответствует шагу в `docs/project/implementation-plan.md`, перебери все шаги с начала документа и найди первый невыполненный, у которого все «Зависит от» выполнены (или отсутствуют). Определи: будет ли задача добавлена и какой step_id.

Покажи: путь создаваемого файла, содержимое записи, что будет удалено/очищено. Если задача из implementation-plan — укажи: «Будет добавлена `{next_task_id}`» или «Следующая задача не добавлена: нет шагов с выполненными зависимостями». Если выполняются условия шага 6 п. 8 — покажи предлагаемую строку для `CHANGELOG.md` → `[Unreleased]` (если файла ещё нет — что он будет создан), иначе укажи «CHANGELOG не обновляется». Дождись явного подтверждения пользователя.

### Шаг 6. После подтверждения — создать completed-запись и обновить backlog

1. Создай `memory-bank/completed-tasks/YYYY/MM/[task_id]_YYYY-MM-DD.md` **копированием** `_template.md` (скелет: `docs/common/memory-bank-usage.md` → «Шаблон карточки»). Секции не удалять.
2. Заполни плейсхолдеры и **## Ссылки:** **Архив:**, **Рефлексия:**, **Ветка:**, **Коммит:** (нет значения — `—`).
3. Если задача была в backlog — удали её из `memory-bank/backlog.md`.
4. Если `{task_id}` соответствует ID шага в `docs/project/implementation-plan.md` (заголовок `#### {task_id}`) — обнови поле **Completed** для этого шага: добавь ссылку `[memory-bank/completed-tasks/YYYY/MM/[task_id]_YYYY-MM-DD.md](memory-bank/completed-tasks/YYYY/MM/[task_id]_YYYY-MM-DD.md)`.
5. **Добавить следующую задачу из многошагового источника:** если закрытая задача из implementation-plan (п. 4 выполнен):
   - Перебери **все** шаги в порядке документа (заголовки `#### {task_id}` вне блоков кода).
   - Для каждого шага проверь: ещё не выполнен (нет в completed-tasks) и не в backlog? Все ли из «Зависит от» имеют ссылку в поле **Completed** (или «Зависит от» = —)?
   - Добавь в backlog **первый** шаг, который не выполнен и у которого все зависимости выполнены (если такой есть).
   - Если ни один шаг не готов — не добавлять.
   - Формат задачи — по `docs/common/memory-bank-usage.md`: чекбокс, **Создано:** (текущая дата), краткое описание из плана, **Источник:** `docs/project/implementation-plan.md ({next_task_id})`, **Причина:** «Следующий шаг после [task_id]» или «Готов к реализации (зависимости выполнены)». Размести в том же разделе приоритета, что была закрытая задача (или «Высокий» по умолчанию).
   - Проверь уникальность: `{next_task_id}` не должен быть уже в backlog или completed-tasks.
6. **Разделы backlog** — разные правила по уровню заголовка:
   - **## (раздел):** не удалять. Если после удаления задачи в разделе не осталось задач и следующая задача не добавлена — оставить заголовок и добавить плейсхолдер `(Нет активных задач)`.
   - **###, #### и глубже (подразделы):** если после удаления в подразделе не осталось задач — удалить подраздел целиком.
7. **Синхронизация product-roadmap.md и статуса фаз** (если п. 4 выполнен — task_id соответствует шагу плана):
   - Открыть `docs/project/product-roadmap.md`, таблицу **«Связь с шагами плана»** (§6).
   - Для каждой строки таблицы: если **все** перечисленные `{task_id}` имеют ссылку в поле **Completed** в `implementation-plan.md` — отметить соответствующий чекбокс в §6 как `[x]`. Пустые строки-плейсхолдеры пропускать.
   - Для §7: если закрытый `{task_id}` указан в пункте долгосрочной цели — отметить этот пункт `[x]`.
   - В §9 **Прогресс** добавить строку: дата завершения (`YYYY-MM-DD`), краткое описание (`{task_id}` / закрытая цель MVP), статус `✅ Готов` — **только если** закрытие шага впервые закрывает цель MVP или долгосрочный пункт, либо завершает фазу плана целиком. Не дублировать строки для каждого мелкого шага.
   - В `implementation-plan.md` → **«Критерии готовности по фазам»**: обновить колонку **Статус** (`✅ Завершена` / `🔄 В процессе`), когда все шаги фазы имеют **Completed**.
8. **CHANGELOG `[Unreleased]`** (опционально, только при выполнении **всех** условий ниже). Каталоги продукта и правила версии — `docs/project/project-structure.md` → «Версия продукта»:
   - В рамках задачи был **`/build`** с изменениями в каталогах продукта из этого раздела
     (не только docs / tests / memory-bank).
   - Изменение **заметно пользователю продукта** (эквивалент
     `feat` / `fix` / `perf` в релизе).
   - В **## Результат** completed-записи или рефлексии есть формулировка для
     пользователя.
   - **Не добавлять**, если задача — dev-only, внутренний refactor без
     пользовательского эффекта, CI/chore/test, чистый Memory Bank.
   - **Действие:** если `CHANGELOG.md` нет — создать (Keep a Changelog, русский)
     с секцией `## [Unreleased]`. Одна строка в `## [Unreleased]` → подходящая
     категория (**Добавлено** / **Изменено** / **Исправлено**). Текст — из
     **## Результат**, не дословно из коммита. Одна задача = один пункт; без
     дублей.
   - Если условия **не** выполнены — секцию `[Unreleased]` не трогать (и не
     создавать файл ради пустого черновика).
   - Итоговая редакция CHANGELOG перед релизом — в **`/release-prepare`**.

### Шаг 7. Подготовить Memory Bank

**Режим A** — задача из "Current Task":

- Перенеси задачу в "Last Completed Task" (task_id, название, дата, статус, ссылка на completed-запись).
- **Статус:** `COMPLETED & ARCHIVED` — только если существуют **оба** артефакта (архив и рефлексия). Иначе — `COMPLETED`.
- Удали секцию "Previous Completed Task" и любые другие секции со старыми завершёнными задачами.
- Очисти "Current Task": только заголовок и плейсхолдер "Нет активной задачи. Запустить `/van [описание задачи]` для начала новой задачи."
- Удали все чеклисты, планы, файлы для изменения текущей задачи.

**Режим B** — задача из "Last Completed Task":

- Добавь в "Last Completed Task" ссылку `**Completed:** [путь]`, если её нет.
- Удали секцию "Previous Completed Task" и любые другие секции со старыми завершёнными задачами.

**Общее для обоих режимов:**

- **activeContext.md:** Current Focus = "Нет активной задачи. Запустить `/van` для инициализации."; Current Mode = "IDLE — ожидание новой задачи"; Next Steps = "Запустить `/van [описание задачи]` для начала новой задачи"; Context for AI — только общая информация о проекте.
- **progress.md:** Добавь или обнови запись `## [Дата]: [task_id] — ЗАВЕРШЕНО` с итогом и ссылкой на completed-запись. **Удали все старые записи о завершённых задачах** — оставь только одну последнюю.

### Шаг 8. Верификация и итог

Проверь: completed-файл создан; задача удалена из backlog (если была); tasks.md — только одна Last Completed Task; activeContext — ожидание `/van`. Если задача была из implementation-plan — проверь, добавлена ли следующая в backlog (если зависимости выполнены); обновлены ли чекбоксы/вехи в `product-roadmap.md` и статус фаз в `implementation-plan.md` (шаг 6 п. 7). Выведи итог и сообщение "Memory Bank готов к следующей задаче. Запустите /van для начала." (если следующая задача добавлена — укажи её ID).

## Не делать

- **tasks.md:** Не оставлять секции "Previous Completed Task" или другие старые завершённые задачи. Только одна Last Completed Task.
- **tasks.md (Last Completed Task):** Не использовать "COMPLETED & ARCHIVED", если нет архива или рефлексии. Только "COMPLETED".
- **progress.md:** Не оставлять старые записи о завершённых задачах. Только одна последняя.
- **backlog.md:** Не удалять разделы `##`. Пустые разделы `##` — оставлять с плейсхолдером `(Нет активных задач)`. Пустые подразделы `###`, `####` и глубже — удалять целиком.
